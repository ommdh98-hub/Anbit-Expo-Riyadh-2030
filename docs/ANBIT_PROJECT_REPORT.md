## 1. هوية المشروع وهدفه

أنبت منصة تجريبية لدعم فرق العناية بالمسطحات الزراعية في فهم قياسات رطوبة التربة وتحديد مواضع القياس الإضافي قبل مراجعة قرار الري. تجمع المنصة بين التحقق من البيانات، والتحليل المكاني، وشرح القرار، وتوثيق إجراءات الري. وهي نموذج محلي للعرض ضمن تحدي الاستدامة والأثر البيئي، وليست منظومة تشغيل ميداني معتمدة. [1، 2]

## 2. المشكلة

قد تتوفر قراءات رطوبة في نقاط قليلة، بينما تختلف حالة التربة داخل المنطقة الواحدة. وقد تكون القراءات قديمة أو غير متحققة أو متعارضة؛ لذلك لا تكفي قراءة منفردة أو متوسط عام لتبرير قرار الري. يحتاج المشغّل إلى معرفة ما الذي تقوله البيانات، وما الذي لا تغطيه، وأين ينبغي أن يقيس بعد ذلك. يستهدف أنبت هذه الفجوة دون افتراض أن نقص المعلومات يعني تلقائيًا الحاجة إلى الماء.

## 3. الحل وتجربة الاستخدام

للأفراد رحلة مستقلة: **اختر مدينتك ← اختر نباتك ← كيف تزرعه؟** تضم 14 مدينة و17 نباتًا، مع إرشادات عناية عامة موثقة المصدر، ودليل الأعشاب الأصلي ومعلومات التربة المبسطة. لا تعرض الصفحة الرئيسية أدوات إدارة الري المهنية. العربية والإنجليزية واتجاها RTL/LTR والمظهران محفوظة. [7]

لفرق المسطحات تنظم الواجهة العمل في ثلاث خطوات فعلية:

1. **اختر المنطقة:** قائمة بالمناطق وحالة مبسطة لكل منها، مع توضيح سبب الحاجة إلى معلومات جديدة، ومنها تقادم القراءات.
2. **افحص رطوبة التربة:** مراجعة المعلومات المتاحة والموقع المقترح للقياس، ثم إضافة قراءة عبر النموذج الموجود. يُعاد التقييم بعد الحفظ، وقد يطلب النظام قياسات أخرى.
3. **شاهد التوصية:** عرض القرار وسببه والتقدير المشروط عند توفره. تبقى القواعد والمصادر والقراءات المستخدمة والمستبعدة ضمن قسم «كيف وصل أنبت إلى هذه النتيجة؟».

لا تُحدَّث أوقات القراءات القديمة تلقائيًا لتحسين المظهر. وتبقى الخريطة والتوأم الرقمي ولوحة المتابعة وسجل الفحص ودليل النباتات والتقارير متاحة. تمر التوصيات بمراحل الاقتراح والاعتماد أو التأجيل، ثم تسجيل التنفيذ بصورة منفصلة؛ **الاعتماد لا يسجل استهلاك ماء ولا يشغّل مضخة**. وبعد تسجيل الري تُستبعد القراءات السابقة له من القرار التالي. [2، 3]

## 4. المعمارية والخوارزميات المنفذة

| الطبقة | التنفيذ الفعلي |
|---|---|
| واجهة المستخدم | Next.js وReact وTypeScript، تنسيق CSS عربي RTL، خريطة SVG ورسوم Recharts |
| خدمات التطبيق | Python وFastAPI، والتحقق من المدخلات بواسطة Pydantic |
| إدارة البيانات | SQLModel مع SQLAlchemy، وقاعدة SQLite محلية |
| منطق القرار | دوال مستقلة في `backend/app/engine.py`؛ لا يعتمد على نموذج تعلم آلي |
| الربط | الواجهة تستدعي API للقياسات والمناطق والتغطية والتوصيات والتنفيذ والتقارير والسيناريو |

يختار المحرك أحدث قراءة لكل نقطة، ويوحّد وحدات الرطوبة الحجمية، ويتحقق من الجودة والحداثة والمنشأ وآخر عملية ري. القيم الخام غير المعايرة لا تتحول تلقائيًا إلى رطوبة حجمية. ثم يفحص التضارب والتغطية وملاءمة الافتراضات وحدود التربة، ويعيد قرارًا مفسرًا: طلب قياس، نقص معلومات، تضارب، مراجعة رطوبة مرتفعة، مراجعة الحاجة للري، أو تأجيله. [2، 3]

**التغطية المكانية:** يقسم المحرك المنطقة المستطيلة إلى شبكة 20×20، ويحسب نسبة مراكز الخلايا الواقعة ضمن نصف قطر محدد من نقطة ذات قراءة صالحة. يقترح أبعد مركز خلية عن أقرب نقطة صالحة، أو وسط المنطقة عند غياب النقاط الصالحة. **هذه تغطية هندسية تقريبية، وليست نسبة ثقة إحصائية أو إثباتًا لتمثيل التربة بالكامل.**

**تقدير كمية الماء:** عند تحقق شروط مراجعة الري وتوفر الافتراضات اللازمة، يحسب النظام:

> إجمالي الماء باللتر = مساحة الري بالمتر المربع × عمق الجذور بالمتر × عجز الرطوبة الحجمية × 1000 ÷ كفاءة الري.

تعتمد النتيجة على صحة المدخلات والتجانس وتمثيل منطقة الجذور. مثال 13,000 لتر الموجود في سيناريو أحواض الأعشاب **اختبار حسابي لمحاكاة محددة، وليس توصية ري ميدانية معتمدة**. [2، 5]

## 5. التوأم الرقمي وتجربة السيناريو

التوأم الرقمي **نموذج تجريبي ثنائي الأبعاد قائم على المحاكاة والتحديث اليدوي**. يعرض الحالة المحفوظة للمناطق ونقاط القياس والفجوات والقرار الحالي، باستخدام إحداثيات مترية محلية وليست GPS. يتحدث بعد عمليات التطبيق أو طلب تحديث البيانات، ولا يمثل اتصالًا حيًا بموقع إكسبو الحقيقي. [4]

تتيح تجربة «ماذا لو؟» إدخال كمية ماء ومساحة وعمق جذور وكفاءة، مع بداية من القراءات الصالحة الكافية أو بداية افتراضية معلنة يكتبها المستخدم. تحسب موازنة حجمية فورية:

> تغير الرطوبة الحجمية = (كمية الماء باللتر ÷ المساحة بالمتر المربع × الكفاءة) ÷ (عمق الجذور بالمتر × 1000).

تُضاف هذه الزيادة إلى رطوبة البداية للمقارنة النظرية. لا يحسب النموذج التبخر أو الصرف أو الجريان أو حركة الماء أو امتصاص النبات عبر الزمن، ولا يتنبأ بقراءة الغد. تُعلّم النتائج المتجاوزة لـ100% حجمية دون قصها أو تفسيرها كصرف. حدود إدارة التربة ليست حدود تشبع.

**السيناريو لا يُحفظ:** لا ينشئ قياسًا أو توصية معتمدة أو حدث ري، ولا يغير تقرير المياه أو القرار الرسمي. [4]

## 6. البيانات ومصادرها

| نوع البيانات | الموجود في النسخة الحالية |
|---|---|
| الموقع والمناطق | حديقة خيالية من خمس مناطق مستطيلة؛ ليست بيانات فعلية لإكسبو |
| القراءات المحفوظة | قراءات عرض مولدة، وإدخالات يدوية عبر الواجهة تبقى موسومة بأنها محاكاة؛ تُحفظ القيمة والوحدة والنقطة والوقت والمصدر والجودة والمسجّل |
| إعدادات المناطق والتربة | حدود رطوبة ومعايير تغطية وعمق جذور وكفاءة وافتراضات تمثيل وتجانس خاصة بالعرض |
| دليل النباتات | خمسة ملفات نباتات أصلية بالموقع، ومستكشف منفصل من17 نباتًا و14 مدينة، و21 دليل عناية عام يغطي المجموعتين؛ بيانات الموقع الأصلية والملاءمة ليست اعتمادًا زراعيًا |
| نتائج السيناريو | حسابات افتراضية مؤقتة منفصلة عن القراءات والعمليات المحفوظة |

يتحقق API من الوحدة والمدى والزمن وانتماء النقطة وحدود المنطقة، ويمنع خلط منشأ البيانات داخل المنطقة نفسها. تدعم البنية وسومًا ومراجع للبيانات الميدانية، لكن **وجود هذه الحقول لا يعني وجود رصد ميداني فعلي**. الرطوبة الجوية ليست رطوبة تربة ولا تدخل بدلًا منها في القرار.

لم تُدمج قاعدة `ENBT.db` في تشغيل الري. يستعمل المستكشف مقتطف أسماء وتقييمات قواعدية منفصلًا، دون سجلات الري أو أرقام الاحتياج أو الطقس؛ ليست بيانات تشغيلية للقرار. لا توجد مجموعات SIMPaCT أو USDA أو ERA5-Land تشغيلية. البحث المستقل على Turfgrass موضح أدناه، ولا يستبدل القياسات. [5، 7، 8]

## 7. التنفيذ والتحقق

سجّل التحقق المحلي الأخير **117 اختبار Python و58 اختبار JavaScript ناجحًا**، مع نجاح TypeScript وESLint وبناء Next.js للإنتاج. أوامر التحقق `node --test frontend/tests/*.mjs` و`bash scripts/test.sh`. تغطي الاختبارات الوحدات والمدخلات غير الصالحة والتغطية والقرارات، وقيود الاعتماد والتنفيذ والتكرار، وحسابات السيناريو وعزلها عن السجلات والتقارير. بقي تحذير إهمال تقني متعلق بـStarlette/httpx لا يفشل الاختبارات. هذه نتائج تحقق برمجي، وليست مقاييس دقة زراعية. [6]

شمل العرض اليدوي المتكامل إضافة قراءة وتحديث التغطية والقرار، وإنشاء توصية واعتمادها وتسجيل تنفيذ تجريبي وظهوره في التقرير، ثم طلب قياس جديد بعد الري. اختُبرت أيضًا تجربة السيناريو وإعادة تعيينها، وثبات التقرير عند الحساب الافتراضي. وفي اختبار المسار الموجّه جرى اختيار منطقة وحفظ قراءة والانتقال إلى النتيجة، والعودة لإكمال القياس عندما لم تكفِ قراءة واحدة.

وثّقت اختبارات الواجهة السابقة عرض الكمبيوتر والتابلت والجوال وRTL. لا توجد حزمة اختبارات واجهة آلية شاملة، ولا دراسة مستخدمين تثبت فهم التطبيق خلال عشر ثوانٍ؛ تبسيط الواجهة هدف تصميمي منفذ يحتاج تقييمًا بشريًا إضافيًا. أُعيد التحقق في 15 أكتوبر، بما فيه رحلة الأفراد وفتح الدليل الموثق، ودخول الدورين وخروجهما، ودورة اعتماد وتنفيذ في قاعدة اختبار معزولة وتصديرCSV. فُحصت العربية والإنجليزية والمظهران والجوال. بقي التحقق من صفحات PDF الجديدة بحاجة إلى حفظ ومراجعة يدوية، ولا يُعلن نجاحه. [6، 9]

## 8. الأثر المتوقع

يساعد أنبت على توجيه الفحص إلى الأجزاء الأقل تمثيلًا، وشرح أسباب تأجيل القرار، والفصل بين التوصية والاعتماد والتنفيذ، وإتاحة سجل للكميات المدخلة. قد يدعم ذلك تقليل الري غير المبرر وهدر المياه بعد التحقق الميداني. **لم يُقَس توفير فعلي للمياه أو تحسن في صحة النبات**؛ إثبات الأثر يحتاج تجربة مقارنة بخط أساس وظروف متقاربة.

## 9. حدود النسخة الحالية

- لا ML تشغيلي معتمد محليًا، ولا اتصال IoT أو تحكم بمضخات. توجد نتائج تدريب وتقييم بحثية منفصلة لا تُستخدم لإصدار قرارات الري.
- لا توصيات ري معتمدة ميدانيًا، ولا نسب توفير مثبتة.
- لا بيانات طقس أو حرارة تربة فعلية مدمجة، والتغطية الحالية لمناطق مستطيلة فقط.
- صلاحية القياسات والحدود الزراعية في العرض تعتمد على افتراضات معلنة، وليست معايرة حساسات أو تحققًا زراعيًا مستقلًا.
- المصادقة المحلية والجلسات وصلاحيات الدورين منفذة ومختبرة؛ النشر التشغيلي والحمل متعدد المستخدمين والتحقق الميداني خارج النطاق الحالي. [2، 4، 6]

## 10. التطوير المستقبلي

تبدأ المرحلة التالية بمعايرة ميدانية للحساسات وحدود التربة وتمثيل عمق الجذور، ثم ربط قراءات حقيقية موثقة واختبار التغطية بحسب اختلاف الموقع والنبات. يلي ذلك دمج طقس ذي مصدر ووحدات وفترات واضحة، وجمع بيانات تشغيل تسمح بقياس أثر الماء وصحة النباتات.

توجد دراسة بحثية منفصلة على Turfgrass تقارن النماذج وخطوط الأساس بفصل زمني2021/2022 وآفاق1/3/6/12/24 ساعة؛ لا تثبت التعميم على الرياض. مستقبلًا يلزم تقييم محلي ومكاني وخط أساس مناسب قبل أي تشغيل. سيناريو24 ساعة والجدولة الحالية محاكاة معلنة بطقس مفترض، لا أتمتة فعلية. سجلات ري ENBT.db تبقى مستبعدة إلى حين توثيقها والتحقق منها. [8]

- اعتماد الصياغة النهائية والشعار وأي شعارات جهات مشاركة، ومتطلبات قالب التقرير والعرض وعدد الصفحات.
- تأكيد أحدث تعليمات المنظمين وموعد التسليم؛ الوثائق الحالية تسجل 16 أكتوبر 2026، الساعة 14:00 بتوقيت الرياض.
- إرفاق أصل موافقة المنظمين ونطاقها بشأن الاستفادة من العمل السابق والعمل المسبق وأدوات AI، وفق تأكيد الفريق المسجل؛ لا يقدم التقرير تحققًا مستقلًا منها.
- توثيق مصادر زراعية موثوقة لخصائص النباتات وحدود الرطوبة وعمق الجذور والكفاءة قبل تحويل افتراضات العرض إلى استخدام ميداني.
- مراجعة بشرية أخيرة للمسار الموجّه على أجهزة العرض واعتماد نسخة التسليم؛ لا تُعد نتائج الفحص البرمجي بديلًا عن تجربة المستخدم أو التحقق العلمي.
